# AIRC - Async IRC Client for Book Downloads

## Aim
A specialized IRC client written in Rust that connects to IRC servers, joins channels,
and facilitates DCC file transfers for downloading books. The client provides an
interactive command-line interface with search capabilities and concurrent download management.

## Core Features Implemented

### IRC Protocol Support
1. Connect to IRC server with configurable timeout
2. Join specified channel
3. Send and receive IRC messages
4. Handle PING/PONG keepalive
5. Support CAP negotiation
6. Graceful disconnect (QUIT command)

### DCC File Transfer
7. Accept DCC SEND requests (case-insensitive)
8. Stream large files with chunked transfers (64KB chunks)
9. Send DCC ACK packets (proper protocol implementation)
10. Handle concurrent downloads in separate tasks
11. Connection and transfer timeouts for stalled transfers
12. Automatic unzipping of search results

### User Commands
13. `/join` or `/j` - Join the configured channel
14. `/quit [message]` or `/q [message]` - Disconnect with optional message
15. `/search <term>` or `/s <term>` - Search for books on IRC
16. `/ss <term>` - Local search within downloaded results
17. `/<number>` - Request book by entry number from search results
18. Raw IRC commands - Any other `/command` sent directly to server

### Configuration
19. TOML configuration file support (~/.config/airc/config.toml)
20. Command-line argument override support
21. Configurable: server, channel, username, download path, timeouts
22. Auto-generated random nickname if not specified

### Error Handling
23. Custom error types with thiserror
24. Proper error propagation with Result types
25. Descriptive error messages with context
26. Graceful error recovery for failed transfers

### Logging & Monitoring
27. Structured logging with tracing framework
28. Colored terminal output (TX/RX messages, timestamps)
29. Download progress visibility
30. Task tracking for graceful shutdown

### Terminal User Interface
31. Terminal user interface (ratatui) with panes, scrolling, mouse, and download progress

## Architecture

### Module Structure
```
src/
├── main.rs          # CLI parsing, config wiring, task orchestration
├── client.rs        # IrcClient, connection/registration, task loops, IRC + DCC dispatch
├── dcc.rs           # DCC file transfer, filename sanitization, unzip
├── commands.rs      # User command parsing and local search
├── net.rs           # Network retry with exponential backoff
├── tui/             # ratatui TUI: App state, rendering, event application, log routing
├── error.rs         # Error types (AircError enum with From implementations)
└── config.rs        # Configuration loading and merging
```

### Core Components

**IrcClient Struct:**
- Stores configuration, connection state, and async task handles
- Manages reader/writer for TCP stream
- Tracks search results and active downloads
- Uses Arc<Mutex<T>> for safe concurrent access

**Async Task Model:**
- `init()` - Send IRC registration
- `write()` - Handle outgoing messages with quit detection
- `cli()` - Process user input from stdin
- `receive_loop()` - Receive and process server messages
- DCC download tasks - Spawned per file transfer

**Protocol Handlers:**
- `create_pong_response()` - PING/PONG handling
- `handle_dcc_send_request()` - Parse and initiate DCC transfers
- `process_command()` - User command processing with regex patterns
- `handle_search_results()` - Filter downloaded search results

**File Operations:**
- `dcc_receive()` - Streaming file download with ACK protocol
- `unzip_file()` - Extract search results (blocking I/O in spawn_blocking)
- `handle_dcc_file()` - Post-download processing and display

## Design Decisions

### Single Server/Channel Focus
- Designed for specific use case (book downloads from IRC)
- Simplified architecture compared to general-purpose IRC client
- Could be extended for multi-server support in the future

### Async Concurrency
- Non-blocking I/O for IRC messages
- Concurrent DCC downloads don't block message loop
- Proper task management for graceful shutdown
- Timeout support prevents hanging on stalled connections

### Configuration over Hardcoding
- All magic numbers extracted to named constants
- Timeouts configurable via config file
- Paths, servers, channels all configurable
- CLI arguments override config file

### Procedural with Structured Data
- Uses Rust structs rather than OOP classes
- Functional approach with clear separation of concerns
- Module-based organization (error, config)
- Ready for future refactoring into more modules if needed

### Error Handling Strategy
- Custom error types provide clarity
- Automatic conversions (From trait) reduce boilerplate
- Errors carry context (server name, file path, timeout duration)
- No silent failures (removed unwrap_or defaults)

### User Experience
- Colored output for readability (RX green, TX red, timestamps gray)
- Timestamps on all messages
- Clear error messages
- Wait for downloads to complete before exit
- Book search results numbered for easy selection

## Security Considerations

### Implemented
- Input validation on entry numbers
- Timeout protection against stalled transfers
- Path safety in file operations
- Filename sanitization on DCC SEND (rejects path separators, traversal, null bytes, reserved names)
- Size limits on downloads (10GB cap)
- No arbitrary command execution

### Future Work
- Hash verification for downloaded files
- Sandboxing for file extraction
- Rate limiting to prevent abuse

## Performance Characteristics

### Optimizations Implemented
- Zero-allocation case-insensitive checks (eq_ignore_ascii_case)
- Compiled regex patterns (once_cell::Lazy)
- Streaming file transfers (no full-file buffering)
- Lock optimization (release before I/O)
- Efficient buffer sizes (64KB chunks)

### Resource Usage
- Memory: O(n) for search results, O(1) for transfers
- CPU: Minimal (mostly I/O bound)
- Network: Efficient chunked transfers with ACK
- Disk: Direct streaming to filesystem
